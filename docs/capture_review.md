# 수집 누락과 소속 판정 보완

2026-11-05 소스 수정 기록입니다. 기존 배포판의 실측 결과와 구분합니다.

- 노드 전체 수집에서도 대표 스레드와 같은 그룹의 스레드를 확인합니다. 별도의 FD 테이블을 가진 스레드에만 남아 있는 소켓 큐도 수집 후보가 됩니다. 공유 FD 테이블은 한 번만 탐색합니다.
- 스레드 목록이 손상되거나 수집 도중 바뀌어도 먼저 확보한 대표 스레드의 후보를 보존합니다. 오류는 불완전 수집으로 기록합니다. 스레드의 TGID를 확인하고 실제 페이지 읽기 전후 검증에도 포함합니다.
- cgroup v1과 v2가 혼합된 환경에서 v2 경로가 루트라는 이유로 v1의 정확한 Pod 경로를 무시하지 않습니다. 전체 항목을 확인하고 서로 다른 대상 경로가 충돌하면 오류로 처리합니다.
- 프로세스 이름에 UTF-8이 아닌 바이트가 있어도 시작 시간을 읽습니다. 이름 이후의 숫자 필드만 해석하며, cgroup 경로의 바이트 검증은 유지합니다.
- 발견 결과에 탐색한 스레드 수와 고유 FD 테이블 수를 추가했습니다. 소켓 자원 탐색 정책 표시는 referenced_socket_queues_and_pod_cache_v5이며 LiME, manifest, ledger 형식은 유지합니다.

프로세스 대표 4,096개, 그룹당 스레드 4,096개, 전체 스레드 16,384개로 제한합니다. 기존 큐당 64 KiB와 추가 페이지 공유 예산 16 MiB, 협력적 탐색 기한 1초를 유지합니다. 한도를 늘려 모든 통신을 수집하는 기능은 아닙니다. 현재 FD에서 도달할 수 없는 소켓, 이미 사라진 바이트와 과거 통신 전체는 보장하지 않습니다.

Linux x86-64 musl 환경에서 자동 검사 84개가 통과했습니다. 새 검사는 개별 스레드만 가진 소켓의 큐 바이트 선택, 공유 표 중복 제거, TGID 변경, 스레드 목록 순환, 전역 탐색 상한, 혼합 cgroup과 비 UTF-8 프로세스 이름을 다룹니다. 합성 커널 구조와 기존 수집 및 검증 회귀 검사입니다. 이 수정본으로 실제 Kubernetes 노드에서 새 덤프를 수집한 검증은 아직 수행하지 않았습니다.

빌드 스크립트는 release 프로필 테스트 후 정적 Linux 실행파일을 만들고 소스 해시와 실행파일 해시를 검사합니다. 새 실행파일과 manifest는 release/review-20261105에 배치합니다. 이전 release/kerneldump는 기존 검증 기록과 함께 유지합니다.
