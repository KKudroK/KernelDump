# KernelDump v1.3.0

코드·소켓·메모리 파일을 찾는 작업에 각각 기회를 주고, 최종 추가 수집 공간도 번갈아 사용합니다. 열린 파일과 매핑에서 큰 적격 파일을 찾았을 때는 제한된 앞부분을 보존하고 빠진 범위를 남깁니다. 닫힌 공유 memfd는 현재 매핑과 역방향 소유 관계를 확인해 수집합니다.

파일 캐시의 소유 관계를 재확인할 때 모든 플래그가 같아야 한다고 요구하지 않습니다. 잠금·참조·쓰기 진행처럼 바뀔 수 있는 값과, 페이지의 연결·크기·내용 유효성을 확인하는 값을 구분합니다. 소유 관계나 필요한 플래그가 바뀌면 계속 거부합니다. 실패 기록에는 실제 비교 주소와 기대값·관측값을 남깁니다.

선택한 Pod의 여러 스레드와 서로 다른 파일 목록을 살핍니다. TCP·UDP·UNIX, 비선형 소켓 본문, 삭제 파일과 메모리 파일, 수정된 실행 페이지를 실제 수집본과 대조했습니다. 수집 정책은 `kernel-focused-v9`이며 전체 RAM·전체 파일·전체 통신 이력을 보존한다는 뜻은 아닙니다. 일부 바이트나 참조 검증이 빠지면 부분 수집으로 기록합니다.

소켓 트리의 한 갈래나 파일 캐시의 한 항목을 읽지 못해도 다른 갈래의 수집을 계속합니다. 열린 파일의 재확인은 해당 번호의 사용 비트만 비교하므로, 다른 파일을 여닫는 동작 때문에 유효한 자료를 버리지 않습니다.

92개 자동 검사를 통과했습니다. AL2023 6.1.189·6.12.113·6.18.56 및 Ubuntu AWS 6.8.0-1067 공식 커널을 별도 부팅해 수집·해시·분석 정답을 대조했고, Ubuntu AWS 7.0.0-1014의 실제 Kubernetes Pod도 수집했습니다. 의존 파일 확인값과 RustSec 검사를 통과했습니다. 이 범위는 전체 AMI 배포 시험이나 모든 커널 설정의 지원을 뜻하지 않습니다.

릴리스와 실행 파일의 버전을 1.3.0으로 맞췄습니다. 이전 릴리스의 별도 내부 버전 표기는 과거 기록에 유지합니다.
