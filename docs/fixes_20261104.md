# 2026-11-04 재점검 수정

이 문서는 최초 수정 단계의 기록이다. 후속 실제 커널 시험에서 파일 캐시 호환성을 추가 수정했으며, 최신 실행 파일과 검증 결과는 [7.0.0-38-generic 검증](kernel_7_0_0_38_validation.md)을 따른다.

버전은 0.1.1, 수집 정책은 kernel-focused-v9를 유지한다. 실행 파일은 release/manifest.json의 SHA-256과 소스 해시로 구분한다. 기존 문서의 VM 수집 결과와 성능 수치는 이번 수정본의 실측 결과가 아니다.

## 수정 내용

1. vendor 파일 110개의 줄바꿈을 각 .cargo-checksum.json에 선언된 원본 바이트로 복원하고, 누락된 cfg-if/Cargo.lock을 복구했다. 체크섬 선언을 새 파일에 맞춰 바꾸지 않았다. .gitattributes의 vendor/** -text는 이후 checkout의 줄바꿈 변환을 막는다. 빌드 스크립트는 빌드 전에 전체 vendor 파일을 검사하며 --check-vendor로 검사만 실행할 수도 있다. cfg-if의 Cargo.lock은 해당 패키지의 ignore 규칙 때문에 새 저장소에 추가할 때 git add -f가 필요하다.

2. ranges.jsonl 한 레코드의 한도를 수집기와 검증기가 같은 상수로 사용한다. 줄바꿈을 포함해 최대 8MiB다. 많은 프로세스가 같은 실행 페이지를 참조하면 기존 1MiB 한도를 넘을 수 있었다. 이제 큰 정상 기록이 검증되며, 8MiB를 넘으면 그 레코드의 LiME 본문을 쓰기 전에 실패 처리한다. 이 제한은 수집기 전체 메모리 사용량의 한도가 아니다. 기존 1MiB 제한의 검증기로 큰 새 기록을 검사하면 거부되므로 수정본 검증기를 함께 사용한다.

3. 네트워크 내용과 관리 정보의 읽기 전후 검사에 FD 소유 연결을 포함했다. 기존 프로세스 식별 검사에 더해 files_struct.fdt, fdtable의 배열과 크기 및 open_fds, 해당 FD 슬롯과 열린 비트, file.private_data, socket.file, socket.sk, sock.sk_socket을 확인한다. 같은 비트맵 안의 다른 FD 변화는 대상 FD의 변화로 처리하지 않는다. 연결 변경이나 읽기 실패는 partial의 근거가 된다.

4. v9의 complete_for_policy 검증은 코드와 자원 수집 결과, 후보와 읽기 수, 오류 목록, 발견 당시 요약, Pod 확인 결과, 공통 예산의 산술 관계와 레코드 안의 참조 검사 결과를 대조한다. 상위 완료 상태만 바꾸어 하위 실패를 숨긴 manifest는 거부한다. 추가 수집 항목이 없던 v4 결과는 계속 검증할 수 있다. 검증은 파일 내부 일관성을 확인하며 전자서명이나 수집 출처 인증을 제공하지 않는다.

## 확인 방법과 범위

회귀 테스트는 실제 수집기와 검증기에 합성 메모리와 BTF를 공급한다. 128개 프로세스의 4,096개 코드 참조, 한 페이지에 집중된 8,191개 참조, 레코드 한도 초과, FD 및 소켓 연결 변경, 다른 FD 비트 변경, 모순된 완료 상태를 포함한다. 테스트 소스는 src/tests/retention_regressions.rs, src/resources/provenance_tests.rs, src/ledger.rs에 있다.

Linux x86-64 musl 환경에서 네트워크를 차단한 상태로 의존성을 빌드한다. 릴리스 스크립트는 테스트 통과, 외부 ELF 인터프리터와 공유 라이브러리 의존성 부재, 개발 옵션 제외, 실행 파일 해시와 내장 소스 해시의 일치를 확인한다. 최종 검사 결과와 실행 파일 식별자는 같은 폴더의 fixes_20261104_validation.json에 기록한다.

최초 수정 단계에서는 실제 Linux 노드에서 새 덤프를 수집하지 않았다. 특히 Ubuntu 7.0.0-38-generic의 실제 수집 호환성, 서비스 영향과 수집 시간은 이번 검증에 포함되지 않는다. 합성 BTF 테스트와 정적 실행 파일 빌드는 그 검증을 대신하지 않는다.

FD와 선택한 소켓 및 skb 필드 검사는 한순간의 원자적 스냅샷을 만들지 않는다. 큐 소속 전체를 다시 순회해 보증하지 않으며, 검사 사이에 값이 변했다 돌아오는 ABA와 본문 변경도 배제할 수 없다. 바이트 확보와 연결 확인만으로 과거 통신, 상대방 수신 또는 실행 성공을 증명하지 않는다.
